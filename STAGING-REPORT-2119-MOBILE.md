### Design readings determined from the spec (recorded here, not silently decided)

1. **A mobile poses from its AUTHORED rest, not poseRig's t = 0.** Step 3.1 defined a tree figure's local-composition rest as the gait adapter's rest (`poseRig(rig, 0, gait, phase)`) — the only rest under which a native bone composes to its native pose. A mobile has no gait: poseRig's rest would bend its hang by a gait's crouch and knee terms (measured on the fixture's shape: a depth-1 bone's rest local angle shifts by the full knee swing, −26° under NOD). §4 is explicit — "Rest angles are the authored hang … the record is the truth" — so `poseFigure` dispatches a mobile to a dedicated composition (`poseMobileFigure` in `rigSources.js`): every bone local, FK from the authored hang, each source evaluated at the part's own phase (ruling 2), `amount` multiplying the local delta — the same local composition as an off-pass tree bone, with the authored hang in place of the adapter's rest.
2. **A phrase bone on a mobile hangs at its authored rest until P6.** Step 3.1's fail-safe reads an unregistered source as absent and the bone "poses natively meanwhile" — a mobile has no native, so its only fallback is the authored hang itself: the delta is zero, the subtree composes from the bone's rest tip, and the entry waits for P6 exactly as a tree bone's does (ruling 8). The sanitizer keeps the entry (syntax-lawful); the pose contributes nothing.
3. **The fixture's sources are authored into its record** (ruling 1 governs the *deal*, which is 3.3's; this step ships the record kind plus one authored fixture, per the step text). The fixture exercises a single (`kineme:rock`, `kineme:bob`, `kineme:bend`), a P5 stack (`kineme:rock+bob` — just an id, per §2), and three amounts (0.5, 1.5, 2 — inside the [0, 2] clamp).

## 2. The build

**`app/src/engine/creatureRig.js`**
- `sanitizeRig` learns its second shape: a `figure: 'mobile'` branch between the linkage and tree branches (branch order preserves today's behaviour for every existing record — a linkage record still takes the beast branch first). The mobile loop mirrors the tree loop's bounds and parents-first discipline with the mobile's rules: ids `^l\d\.\d$` and role `'limb'` only (ruling 5 — no head); every kept bone must carry a valid motion under `sanitizeBoneMotion(b.motion, 'mobile')` — a value the existing validator already handles correctly ('gait'/'linkage' drop, kineme ids checked against the library, phrase ids syntax-lawful, amount clamped [0, 2]). A bone with no valid source drops **and its subtree drops with it** (a child whose parent never enters `seen` is skipped — the parents-first rule makes it mechanical, as §4 says).
