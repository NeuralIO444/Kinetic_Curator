## Fix round (QA round 1: BLOCKER + NOTE → this commit)

QA round 1 returned one BLOCKER (the CSP: detection built, but the bundled desktop shell's own policy forbade the fetch it exists to make) and one NOTE (the registry accepted measurement-inconsistent records). Matt ruled the CSP change rides with S1 (recorded on the issue, 2026-11-10). This round implements that ruling plus the NOTE and one copy consequence; it supersedes the "Tauri CSP allowance — deliberately NOT changed" line in *Left out* above.

1. **CSP allowance (Matt's ruling).** `src-tauri/tauri.conf.json`: exactly `http://127.0.0.1:11434` added to `connect-src` in BOTH the release `csp` and the `devCsp` — no other origins, no wildcards, no scheme-wide `http:`. The pin in `app/src/assets/tauriCsp.selfcheck.mjs` now runs over both policies: it requires that one origin in connect-src, permits it in no other directive, and still forbids every other http(s) connection; the justification (MegaMind local-model link, #1525, Matt's ruling 2026-11-10 — 127.0.0.1 can only ever name the visitor's own machine) is written in the selfcheck, in the repo's voice. (tauri.conf.json is JSON and carries no comments; the selfcheck is the config-adjacent record.)
2. **Registry measurement invariant (QA NOTE).** QA probed that contradictory records validated — tier A with `probeClean:false`, tier A with `probeMs:null`, tier A with `probeMs:999999` — and `consumerEnabled` trusted the tier field alone. `app/src/composition/capabilityRegistry.mjs` now fails closed on measurement-inconsistent records: a tier A or B record is invalid unless `probeClean` is true and `probeMs` sits inside that tier's bound (the bounds are imported from `classifyTier`'s own constants in megamindLink — `TIER_A_MAX_MS` 3000 / `TIER_B_MAX_MS` 8000 — never re-stated), and `consumerEnabled` re-validates every record it is handed, so a tier field alone enables nothing. Selfcheck cases cover QA's three contradictory records (validation refuses them; `persona.perBar` stays disabled) plus the honest-record control, and the tier-B analogues.
3. **Desktop-shell endpoint gate copy.** A consequence of item 1: inside the shell, only the one allowed origin can ever connect, so a typed endpoint at any other origin is refused by the shell itself. `megamindLive.connect()` now names that gate (`shell-endpoint`) when the shell signal is present and the endpoint's origin is not the allowed one — refused before any fetch, instead of collapsing into the generic unreachable copy. The shell signal is the app's one existing check (`isTauriRuntime` from `platform/desktop.mjs`, the same one mindApple uses, already injected into the driver as `isDesktop`); the origin test is a pure helper in megamindLink (`isDesktopShellEndpoint`). Covered in the selfcheck with the shell signal injected (non-House endpoint → `shell-endpoint`, zero fetches, copy names the allowed address; outside the shell the same endpoint is fetched and judged on its answers).

**Acceptance surface.** The DEV panel is dev-only by design (the #691 decision in `app/src/composition/PanelRegistry.js` — unchanged by this round), so S1's acceptance surface is the Tauri dev shell and the Vite dev app. The release bundle carries no DEV panel; MegaMind reaches release only when its user-facing home is ruled later. Item 1's release-`csp` allowance is in place ahead of that day, so the ruled home will not need a second security decision to talk to Ollama.
