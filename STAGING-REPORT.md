## Premise check (first-class, per the shelf's standing stop-rule)

**Premise TRUE — built as contracted.** Searched code + git history before writing anything: no slit-scan, scan-direction, or delay-map code exists anywhere (`slit|stargate|scanDirection` → zero hits in app/src and in `git log --all`); accum.mjs had no `scan` identifier at all. Vision §2.6 names slit-scan as the *later variant* of the shipped B3 echoes ("per-column tap selection from a displacement map… Same infrastructure, one extra map") — the issue is that variant's contract, and B3 (ring, weights, memory gate) is on main as it describes. No recorded decision contradicts it. Two design readings were mine to make, both recorded here and on the code:

1. **Selection depth.** The issue says a column *samples a different delay* and speaks of "the mixed frame's per-column source-tap indices" — I read selection as: the column shows ONE frame (the one from *d* steps ago), never the additive stack. The depth cue is the tap's own echo weight (delay 0 = live at 1.0, delay *d* at `echoWeights[d−1]`), so the smear still fades with age exactly like echoes do. The alternative (additive mix with per-column weights) would show the live frame everywhere and is not slit-scan.
2. **SCAN semantics.** "Delay varies linearly across x from 0 to the full ring depth, steepness set by SCAN": delay(u) = floor(ramp(u) · scan · (taps+1)) — at scan = 1 the ramp sweeps the full ring depth across the frame; at 0.5, the recent half; at 0, all delay 0. Ramp/direction are baked into the LUT, so the shader only ever samples a delay (the issue's v2 requirement).

## What shipped (plain language)

Echoes used to mix whole past frames everywhere at once. Now, with SCAN up, each column of the frame picks a *different moment*: the left edge shows now, the right edge shows the oldest echo in the ring, and columns between step through the ring — so a moving mark smears sideways through time in discrete bands, the stargate / slit-scan look. A "deep past" toggle flips which edge is oldest. SCAN = 0 is the old mix, untouched. The scanned ghosts then trail, fade (spectrally, #1800), flow and glow exactly like live light, because scan only changes how the incoming frame is mixed.

## How (specifics)

- `app/src/gl/accum.mjs`
  - `scanDelayRamp({taps, scan, direction})` — the one derivation: a 256-texel LUT of quantised integer delays (0 = live, *d* = frame from *d* steps ago), linear ramp, direction flip baked in. `scanDelayAt(lut, x, w)` — the exact texel indexing the GPU's NEAREST sampling performs, exported for the mirror. `SCAN_LUT_WIDTH = 256` (the issue's ≤256px ceiling; the LUT is a 1 KB texture, not a target).
  - `accumRecipeParams` gains `scan` (clamp01) + `scanDirection` (±1 via the new `sanitizeAccumScanDirection`; `sanitizeAccumScan` alongside, the sanitizeAccumEchoes pattern). Both ride the params through `applyAudioEnvelope` / warp spreads untouched (audio modulates keep/optics, never the time display).
  - `ECHO_FS` extended, not forked: at `u_scan > 0` it samples the delay LUT at `v_cuv.x`, clamps the delay to `u_ntaps` (early-sequence honesty), and selects that one frame at its tap weight; at `u_scan = 0` the body is the pre-#1804 additive mix operation-for-operation. The delay is a *sampled value* — the v2 general map is a LUT-source change, per the issue.
  - Engine: a 256×1 RGBA8 NEAREST delay texture, re-uploaded only when (echoTaps, scan, scanDirection) changes; bound at unit 5 in the echo pass; deleted in dispose. **The dry-path uniform-location list in createAccum is hardcoded and separate from ACCUM_PROGRAMS** — `u_scanDelay`/`u_scan` were added there too; missing them makes the uploads silent no-ops (this bit during development: GPU ran the additive path while Node tests passed; the browser parity probe caught it — see Verification).
  - Mirror: `mirrorAccumStep`'s echo stage branches on `p.scan > 0` into per-column selection using the same ramp + indexing + clamp; integer delays make parity exact by construction.
  - Cost: the echo program's declaration gains the two uniforms; tier/memory/time unchanged (same pass, ring dominates; notes record the LUT rides the pass). The ≥2048px memory gate is untouched.
- `app/src/gl/sceneContract.js` — `accum.scan` / `accum.scanDirection` sanitized at the boundary, **keys present only while scan > 0** (the squash/cellShed precedent), so unscanned contracts and their hashes are byte-identical to before.
- Still path (share-or-refuse): `accumStill.mjs` flags `--scan` / `--scan-direction ltr|rtl` → contract + `renderAccumViaGL` opts (glDriver) → `glHarness.html` → `renderer.renderAccumSequence` → the same `accumRecipeParams`. Live path: `liveLoop.mjs` feeds `layoutParams.accumScan` / `accumScanFlip` into the same params.
- UI: `AccumFamily.jsx` — SCAN slider appears only when echoes > 0 (the control earns its surface when its prerequisite exists, per the issue), and the DEEP PAST side toggle (RIGHT/LEFT) appears only while SCAN > 0. `layout-modes.js` carries **no defaults and no PARAM_SPEC entry** for the new params — a recorded decision of this slice, see Verification: the replay gates hash the resolver output that defaults are normalized into, and PARAM_SPEC membership requires a default; the params therefore live on the event path only, readers treat absent as 0/unflipped, and the recipe clamps.
- `app/src/gl/debug/sweepEffects.mjs` — the sweep's echo declaration learns the two new uniforms (drives the pre-#1804 mix, u_scan = 0; the #1800 fade-def precedent).
- `app/src/gl/parity/accumProbe.html` — probe params gain scan/scanDirection.
- `docs/ACCUM.md` — B3 gains the slit-scan paragraph (surgical edit; the file is prettier-drifted on main and was NOT reformatted).
