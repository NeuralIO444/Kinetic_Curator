## Context

`data/quality.js` caps composition to protect *interactive* performance: PERF
allows 180 shapes and disables mirror entirely; BALANCED allows 420; HIGH
allows 800. These are soft ceilings for live performance — the file says so.
At render time there is no interactivity to protect, so the caps buy nothing.

Already working, do not rebuild:
- `STOP` freezes motion (`running` gates `useCanvasLife`, `useContinuousLife`, `useSwarmTick`).
- `exportSnapshot` rasterizes the live SVG node at 1×/2×/4× (1920×1080 / 3840×2160 / 7680×4320) — a true re-render from vectors, not an upscale of screen pixels.
- Snapshot records carry seed, resolution, timestamp, full layout config, palette id, and a jpeg thumbnail.

Missing:
1. Render does not lift quality caps — a 4× export of a PERF session is an 8K image of a 180-shape composition.
2. The flow isn't presented as a flow — resolution is a `<select>` in OUTPUT, `S` fires instantly, nothing signals "this is now a final."

## Spec

New action `renderFinal({ resolution, uncapped })`:
1. Snapshot current state (seed, layoutParams, paletteId, enabledAssets).
2. If `uncapped`, recompute placements with caps lifted — `maxCount` / `maxParticles` raised, `allowMirror` forced true.
3. Rasterize at `resolution` via the existing `exportSnapshot`.
4. Restore live state.

UI: a RENDER block in OUTPUT — resolution selector, an UNCAPPED toggle, one primary button. Keep the existing instant `S` snapshot as the quick-grab.

## ⚠ Open decision — blocks implementation

Placements are seeded. Changing count doesn't add detail to the existing composition — it consumes the RNG stream differently and produces a *different* image. So:

- **(a) Render matches preview.** Caps stay, uprez is pixels only. Predictable, wastes the headroom.
- **(b) Render goes fuller.** Caps lift, same seed, denser composition — but not the frame you were looking at when you hit pause.

Recommendation: **(b)**, with (a) available via the UNCAPPED toggle defaulting off. This is an artistic call, not a technical one — needs a decision before implementation starts.

## Risks to verify

- Browser canvas limits at 7680×4320 with 800 shapes + mirror — Safari caps canvas area more aggressively than Chrome. Test before shipping 4×.
- `exportSnapshot` is async via `img.onload`; a long render needs progress feedback or it reads as a hang.
